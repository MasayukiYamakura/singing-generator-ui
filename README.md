# S-Generator UI — スマホ基本版

## 工程別の制作画面（v0.12.0）
画面を「曲を選ぶ」「音源を用意」「編集・補正」「試聴・書き出し」「MV制作」の5工程へ再配置。既存の入力ID、設定JSON、履歴と音声処理は維持する。接続情報は曲選択画面の開閉可能な設定領域に置く。工程移動は随時可能で、直近の工程は同じタブ内で復元する。

波形カードは暗い背景に明るい文字を明示し、時刻目盛りと説明をDOMテキストで表示する。Canvasは波形とドラッグ領域だけを描画する。トリミング端のタッチ判定は左右24 CSS px、数値欄は代替操作、共通時刻目盛りで2トラックを読む。VoiceOver用のCanvas説明と数値入力を維持する。

保存済みの歌声・伴奏は「保存済み音源の波形を読み込む」で非公開ジョブから最大1200点の概要波形を取得できる。波形点だけ端末のlocalStorageに保存し、音声や署名URLは保存しない。期限付きURLはその場の単独試聴に使い、正確な配置重ね試聴には端末の元ファイルを選択する。アップロード準備が終わったら、選択済みファイルを同じ画面で自動登録する。画面を閉じてファイル選択が失われた場合は再選択を案内する。

検証：Nodeのロジック試験、WebKitの320/390/430pxで工程移動・文字色・横はみ出し・ボタン高さ・コンソールエラーを確認。処理側 `preview_inputs` は保存済みプロジェクトの素材だけを読み、署名URLは暗号化応答にのみ含める。iPhone実機と本人音源の聴感は別評価。

## 完成曲からの2音源分離（2026-11-17）
完成曲1ファイルを非公開登録し、独立ジョブで歌声と伴奏を生成。各音源を試聴・ダウンロードし、採用すると既存のお手本と伴奏に反映する。本人歌声は保持する。履歴から再取得・分離出力の削除が可能。処理側の正本は `docs/TWO_STEM_SEPARATION.md`。モデルの品質は実曲で試聴して決める。

現行機能の一覧は処理リポジトリの `docs/CURRENT_SPEC.md` に集約しています。2026-11-17に3音源のAI歌声お手本モードを追加。本人歌声・伴奏・お手本歌声を登録し、移調差、音程、強弱（最大±2/3 dB）、軽いノイズ低減を設定します。照合不能時はお手本由来の音程・強弱補正を控えて結果に要確認を表示します。BandLabやSunoの非公開DSPを再現するものではありません。

画面上部の「← V-Generatorへ（動画制作・投稿）」から、動画制作・投稿画面を別タブで開けます。素材・設定・トークンはリンクへ含めません。
GitHub Pagesで公開する画面。処理用の非公開 singing-generator と分離しています。
`npm test` で基本ロジックを確認。ビルド不要。Pagesはmainルートを公開。

公開するのは画面コードのみです。秘密鍵・個人の音声・プロジェクト情報をこのリポジトリに置かないこと。
要件と設計の正本は処理用リポジトリのdocs/です。

## 初回
処理リポジトリへのContents/Actions read-writeに限定したFine-grained PATを入力。
Cloudinary Secretsは処理用リポジトリにのみ登録します。
音声なしの端末内操作デモは接続不要、クラウド合成音テストはGitHubのみ必要。

## 制限
実声品質・iPhone実機・Cloudinary実接続は素材/Secrets未提供のため未承認。
音声はmono24kHzの実験エンジン。フレーズ編集・MIDI読込・お手本解析・時間調整・部分キャッシュは第3段階で追加。複数テイクは次段階。
非公開署名URLは端末のRSAキーで復号、期限切れ時は履歴から再取得。
自動削除はありません。個別の出力削除はCloudinary出力のみです。「音源の整理・削除」で入力とActions成果物を含め手動で整理できます。

第3段階仕様：処理用リポジトリdocs/PHASE3.md。区間調整と旧版からの修正版作成に対応します。

第4/5段階：追加テイク4件、候補試聴・固定、MIXプリセット・詳細設定・グリッド候補。複数テイク操作デモは接続不要、実処理の合成音テストはGitHub接続が必要です。

## 2トラック楽曲制作（2026-11-17）
処理側の仕様正本：singing-generator/docs/TWO_TRACK_STUDIO.md。
歌声と伴奏のファイルを選ぶと「2トラック編集」に波形を表示する。中央をドラッグして曲内の位置を移し、左右の端でトリミング。秒数欄で微調整する。設定は「設定を保存」。ブラウザを再起動した場合は同じ音声ファイルを再選択して波形を確認する。
「編集位置を試聴」は配置・トリミングだけの端末内確認。加工音は「音声を補正する」完了後に非公開リンクで試聴する。キー候補は解析で表示してから手動採用。ジャンル別ミックス提案、曲内の音量カーブ、任意のハモリ、8系統のマスタリングは処理要求へ渡す。
完成ミックス、選択時のマスタリング完成版、歌声と伴奏のステムをダウンロードできる。MVへは完成版を、歌詞同期の照合へは歌声ステムを選択する。BandLabと同じ名称・アルゴリズム・音色ではない。

# タイムラインと音源整理（2026-11-24）

「編集・補正」の共通タイムラインは中央ドラッグで位置、端でトリミング、空白またはスクロールモードで表示移動ができます。表示幅、2本指ズーム、1秒吸着、0.01/0.1秒の微調整、数値入力、戻す・やり直す、編集の保存に対応します。左端トリムは配置開始も同じ秒数だけ動かします。保存済み概要波形だけでは重ね試聴できないため、元ファイルを端末で再選択してください。

上部の案内は準備・アップロード中の画面維持とクラウド処理中の離脱可否を区別します。離脱後は同じ端末で接続・状態更新します。MVの待機は「続きの生成・回収」が必要です。

「試聴・書き出し」の「音源の整理・削除」は、保存音源の件数を確認してから、入力のみ、または当該曲の入力・出力・Actions成果物を二段階で確認して削除します。試聴やダウンロードだけでは削除しません。参照中の分離音源は個別削除できません。MV素材、Git履歴、外部バックアップ、端末に保存したファイルは削除対象外です。

## 共通タイムラインとミュート（v0.14.0）

歌声・伴奏の波形を同じ時間目盛りで上下に並べ、各波形の左端にトラック名、M（ミュート）とS（ソロ）を配置しました。トラック名または波形を選ぶと、そのトラックの位置とトリミング欄を表示します。全体波形と表示幅・表示開始で長い曲の目的位置へ移動できます。中央ドラッグは配置、左右の端は非破壊トリミング、数値欄と微調整も従来通りです。

M/Sは端末内の2トラック重ね試聴にだけ適用し、再生中の切り替えにも即時反映します。ミュート中は波形を暗く表示します。MとSが同時ならMを優先します。出力の音量や保存される設定JSONには反映しません。完成音源のバランス変更は「自動ミックスと手動調整」を使います。曲を切り替えたときはM/Sを解除します。保存済み概要波形の表示は可能ですが、重ね試聴には元ファイルの再選択が必要です。

検証：Nodeの編集状態・試聴中のM/S音量制御、WebKitの320/390/430pxで左右のMボタン、トラック切り替え、数値調整、横はみ出しを確認します。
