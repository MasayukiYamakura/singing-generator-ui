# S-Generator UI — スマホ基本版
GitHub Pagesで公開する画面。処理用の非公開 singing-generator と分離しています。
`npm test` で基本ロジックを確認。ビルド不要。Pagesはmainルートを公開。

公開するのは画面コードのみです。秘密鍵・個人の音声・プロジェクト情報をこのリポジトリに置かないこと。
要件と設計の正本は処理用リポジトリのdocs/です。

## 初回
処理リポジトリへのContents/Actions read-writeに限定したFine-grained PATを入力。
Cloudinary Secretsは処理用リポジトリにのみ登録します。
音声なしの端末内操作デモは接続不要、クラウド合成音テストはGitHubのみ必要。

## 制限
実声品質・iPhone実機・Cloudinary実接続は素材/Secrets未提供のため未承認。
音声はmono24kHzの実験エンジン。フレーズ編集・MIDI読込・お手本解析・時間調整・部分キャッシュは第3段階で追加。複数テイクは次段階。
非公開署名URLは端末のRSAキーで復号、期限切れ時は履歴から再取得。
入力の自動削除は未実装。画面の出力削除ではCloudinary出力のみ削除し、入力とActions artifactは残ります。

第3段階仕様：処理用リポジトリdocs/PHASE3.md。区間調整と旧版からの修正版作成に対応します。

第4/5段階：追加テイク4件、候補試聴・固定、MIXプリセット・詳細設定・グリッド候補。複数テイク操作デモは接続不要、実処理の合成音テストはGitHub接続が必要です。


## 2026-11-01 接続修正（v0.5.2）
接続確認URLの末尾スラッシュでGitHub APIのOPTIONSが404となり、ブラウザでFailed to fetchが発生していた。
リポジトリ直下のURLを末尾スラッシュなしへ修正。通信失敗とHTTP 401/403/404の案内を区別する。
トークン値・権限の変更、Cloudinary Secretsの再登録はこの修正には不要。
core.js/app.js/index.htmlの版を更新し、公開後は ?v=0.5.2 で読み直す。
回帰テスト：直下/子API URL、ヘッダーのみの認証、ネットワーク例外/HTTPエラー分離。
実トークンによる本人の接続成功は利用端末で再確認が必要。テストに本人のトークンは使用しない。

## 接続の追加切り分け（v0.5.3）
v0.5.2でも利用端末でFailed to fetchが続くとの報告。本人の環境での原因は未確定。
fetch成功後のresponse.json()中のストリーム失敗が従来のcatch外だったため、RESPONSE_READ_ERRORとして扱う。
入口と接続モジュールをapp-v0.5.3.js/core-v0.5.3.jsの固有ファイル名へ変更し、実行中のCLIENT_BUILDを画面に表示。
headerの版番号だけでは動作中JSの版を判定しない。更新時は固有ファイル名とCLIENT_BUILD、互換入口を同時更新する。
接続失敗時に入力/リポジトリ/ワークフロー/一覧の工程と安全なエラーコードを表示。接続失敗したAPIオブジェクトは解除。
「トークンなしで通信診断」はapi.github.comへの基本GET/バージョンヘッダー付きGETのみ。認証・リポジトリ名・保存トークンを送らず、10秒のタイムアウト付き。
診断でHTTPが返っても、本人トークンの正しさや非公開リポジトリへの接続成功を保証しない。
